### 编号: MF-2026-005
- **日期**: 2026-09-17
- **问题描述**: 4 项改进代码需要重新打包为可交付的 Windows 安装包；同时需修复打包过程中暴露的两个真实缺陷：
  1. 打包产物将整个项目（含 node_modules、构建缓存、旧版本备份、日志、临时脚本）全部塞进 `app.asar`，体积膨胀到约 966 MB；
  2. 应用在部分 Windows 环境下渲染进程沙箱初始化失败，窗口一闪而过（`render-process-gone reason:"killed"`），必须手动追加 `--no-sandbox` 才能启动。
- **修改方案**:
  1. **依赖分层**：将 17 个仅由 Vite 打包进前端的运行时依赖（vue / pinia / tiptap / echarts 等）从 `dependencies` 迁到 `devDependencies`，`dependencies` 置空，避免 electron-builder 无条件收集生产依赖。
  2. **打包白名单**：新增 `electron-builder-override.json` 作为唯一打包配置源，显式声明 `files` 白名单（仅 `dist/**`、`electron/dist/**`、`package.json`）并排除 `src/`、`scripts/`、`docs/`、`dist_old_*`、`node_modules`、`*.map`、`*.log`、`*.ps1`、`*.md` 等。
  3. **绕过 exe 重写失败**：`electronDist` 指向预解压 Electron 发行目录 + `win.signAndEditExecutable:false` + `disableAsarIntegrity:true`，改由独立进程脚本 `scripts/patch-exe.js` 补写图标与版本资源（进程隔离规避本机文件句柄竞争）。
  4. **沙箱兼容修复**：在 `electron/main.ts` 顶部（app ready 之前）对 Windows 平台显式 `appendSwitch('no-sandbox')`、`disable-setuid-sandbox`，并 `disableHardwareAcceleration()`；保留命令行参数优先级，不覆盖用户显式传入的参数。
  5. **安装包命名规范化**：通过 `extraMetadata` 固定 `name/productName/version/description/author`，`win.artifactName` 设为 `MindFlow-Setup-${version}-${arch}.${ext}`。
- **涉及范围**:
  - `package.json` - 依赖分层、版本号升至 1.0.1
  - `electron-builder-override.json` - 新增，打包配置唯一事实源
  - `scripts/build-win.ps1` - 新增，五步打包流水线
  - `scripts/patch-exe.js` - 新增，exe 图标与版本资源补写
  - `electron/main.ts` - 新增 Windows 沙箱与 GPU 兼容处理
- **验证方式**:
  1. 校验 `app.asar` 条目数与顶层目录，确认无 node_modules / 构建残留
  2. 读取产物 exe 资源，确认版本号、产品名、图标组与图标尺寸数量
  3. 无任何启动参数直接运行 `win-unpacked/MindFlow.exe`，确认窗口出现且渲染进程不崩溃
  4. 静默安装到独立测试目录，确认目录结构完整、快捷方式与注册表项写入正确
  5. 从安装目录启动应用，确认进程存活、窗口标题正确
  6. 运行卸载程序，确认安装目录、开始菜单、桌面快捷方式、注册表项全部清除
